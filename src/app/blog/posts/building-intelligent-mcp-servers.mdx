Claude, ChatGPT, and other LLMs are incredibly capable — but they're still limited.

- Access your internal APIs

- Perform real-time actions on your systems
- Automate workflows that are unique to your organization

Until now.

## Introducing MCP (Model Context Protocol)

Model Context Protocol (MCP) is a new open standard that lets you extend AI assistants with custom tools.

Think of it as "plugins for AI" — you define the actions your AI can take, and the AI intelligently decides when and how to use them.

Instead of saying:

> "Add a new task for me"

…you expose a tool named `create_new_task`, and the AI automatically figures out the parameters, context, and execution.

## Why MCP Matters

- Gives AI Superpowers — It can now take real actions, not just give answers.
- Type-Safe — You define the exact structure of each tool's parameters.
- Secure — You choose what the AI can access.
- Standardized — Works with Claude, ChatGPT, and any MCP-compatible client.

## Real-World Analogy: Task Management MCP Server

Let's walk through a simpler, universal example: a Task Management MCP Server.

Imagine you could talk to an AI like this:

> "Create a new task: Fix login bug, assign it to Sarah, and set priority high."

The AI doesn't just understand — it acts. It:

1. Fetches your team members
2. Identifies "Sarah" in your system
3. Creates a new task via your internal API
4. Confirms completion

## Architecture Overview

This MCP server exposes a few essential tools:

| Tool | Description |
|------|-------------|
| `list_team_members` | Get available users to assign tasks |
| `create_new_task` | Create a new task with title, description, assignee, and priority |
| `list_open_tasks` | View all ongoing tasks |
| `update_task_status` | Change task status (e.g., In Progress → Done) |
| `delete_task` | Remove a completed or invalid task |

### Folder Structure

```text
src/
├── tasks/
│   ├── task.tools.ts
│   ├── task.service.ts
│   └── dto/
├── users/
│   └── user.tools.ts
├── common/
│   └── utils/
│       └── response.util.ts
└── main.ts
```

Each folder represents a logical module. Tools simply act as the MCP interface — while business logic lives in services.

## Centralized Response Handling

Instead of repeating response formatting everywhere, we define one `ResponseUtil`:

Before:

```javascript
return {
  content: [{ type: 'text', text: JSON.stringify({ success: true, data }, null, 2) }]
};
```

After:

```javascript
return ResponseUtil.success('Task created successfully', data);
```

A single class standardizes responses, making tools clean and predictable.

## The Importance of Naming

Tool names are crucial — the clearer they are, the smarter the AI's decisions.

| Bad naming | Good naming |
|---|---|
| `create_entry` | `create_new_task` |
| `fetch_info` | `list_open_tasks` |
| `update` | `update_task_status` |

Descriptive names make it obvious what the tool does — no extra prompt tuning required.

## How the AI Orchestrates Actions

The user says:

> "Close all tasks assigned to Sarah that are marked as completed."

The AI inspects available tools:

- `list_team_members`
- `list_open_tasks`
- `update_task_status`

The AI figures out the sequence:

1. Calls `list_team_members` to find Sarah's ID
2. Calls `list_open_tasks` to find tasks assigned to her
3. Calls `update_task_status` on each completed task

The user receives a confirmation like:

> Closed 3 tasks assigned to Sarah

You never had to tell the AI how to do it — you just defined what's possible.

## Build Your First MCP Tool

Here's a minimal example of a tool built using `@rekog/mcp-nest` and `zod`:

```typescript
import { Injectable } from '@nestjs/common';
import { Tool } from '@rekog/mcp-nest';
import { z } from 'zod';

@Injectable()
export class TaskTools {
  @Tool({
    name: 'create_new_task',
    description: 'Create a new task with title, description, and priority',
    parameters: z.object({
      title: z.string().min(3),
      description: z.string().min(10),
      assignee_id: z.number(),
      priority: z.enum(['low', 'medium', 'high']),
    }),
  })
  async createNewTask(params: any) {
    // Example business logic
    const task = await this.taskService.create(params);
    return { success: true, data: task };
  }
}
```

The library handles:

- Schema validation with Zod
- Tool discovery and registration
- JSON response formatting
- MCP protocol compliance
